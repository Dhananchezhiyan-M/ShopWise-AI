5. Why was config.py created?
    Because ShopWise AI has many settings that different parts of the application need to access.
    Instead of putting those settings throughout the code, we keep them in one central configuration file.
Without config.py, you might end up doing this in different files:

database.py       → database URL
rag.py            → ChromaDB location
gemini.py         → Gemini API key
main.py           → port
cors.py           → frontend URLs

That's messy.

Instead:

                 config.py
                     │
       ┌─────────────┼─────────────┐
       ↓             ↓             ↓
   Database         RAG           Gemini
       │             │             │
   SQLite         ChromaDB        LLM

6. healthy.py:
What it does & Why:
  • Defines a simple GET /api/health endpoint that returns { "status": "ok", "app": "ShopWise AI" }.
  • We use this to instantly verify that the backend server is online, healthy, and ready to receive requests.

7. router.py:
    What it does & Why:
      • Acts as the central traffic controller that bundles all individual endpoint modules (health, search, price analytics, reviews RAG, recommendations) into one master
  router.
      • Instead of registering 20+ routes inside main.py, router.py keeps them neatly organized under the /api prefix.
    
                   router.py (/api)
                          │
       ┌───────────┬──────┴────┬───────────┬─────────────┐
       ↓           ↓           ↓           ↓             ↓
    /health     /search    /analytics   /reviews    /recommend

8. main.py:
    What it does & Why:
      • The root entrypoint of the entire backend application that Uvicorn executes.
      • Initializes the FastAPI application instance, sets up interactive Swagger docs (/docs), and attaches the master /api router.
      • Configures CORS (Cross-Origin Resource Sharing) middleware to allow our React frontend (port 5173) to securely make API requests to the Python server (port 8000).
    
                    React Frontend (http://localhost:5173)
                                    │
                                    ▼ (HTTP Request)
                             FastAPI main.py
                                    │ (CORS Allowed)
                                    ▼
                           Master api_router (/api)

15. database.py:
    What it does & Why:
      • Configures the SQLAlchemy database engine connected to SQLite (shopwise.db).
      • Provides the get_db dependency that opens a database session for each incoming API request and automatically closes it when finished to prevent
  memory/connection leaks.


16. canonical_product.py:
    What it does & Why:
      • Defines the CanonicalProduct database model representing a master product (e.g. Lenovo IdeaPad Slim 3).
      • Groups all different hardware configurations (8GB vs 16GB RAM) and color variants under one single canonical parent.

17. product_variant.py:
  • Defines the ProductVariant model for exact hardware configurations (RAM, SSD, CPU, Battery, Screen Size).

18. store.py:
  • Defines the Store model representing supported e-commerce retailers (Amazon, Flipkart, Croma).

19. store_listing.py:
  • Defines the StoreListing model storing live selling prices, MRP, in-stock status, store ratings, and direct purchase URLs.

20. price_history.py:
  • Defines the PriceHistoryRecord model storing time-series historical price logs for Pandas trend calculations.

21. models/__init__.py:
  • Packages all 5 database models so SQLAlchemy can register their relationships and create tables in one go.

22. init_db.py:
  • Connects to SQLite and automatically creates all 5 database tables and indexes on application boot.

23. schemas/store.py:
  • Pydantic v2 schemas for validating and serializing Store API request/response payloads.

24. schemas/price_history.py:
  • Pydantic v2 schemas for validating historical price logs and time-series records.

25. schemas/store_listing.py:
  • Pydantic v2 schemas for retailer listings with nested store details and pricing data.

26. schemas/product.py:
  • Pydantic v2 schemas for CanonicalProduct and ProductVariant data models with computed best prices.

27. schemas/analytics.py:
  • Pydantic v2 schemas for 30/90-day moving averages, price drop %, and Buy/Wait verdict badges.

28. schemas/recommendation.py:
  • Pydantic v2 schemas for parsed search criteria, multi-factor scores, and AI recommendation explanations.

29. schemas/__init__.py:
  • Central package exporter for all request and response validation schemas.
